# `spikes/` — exploratory spike reviews

A **spike** is a time-boxed, throwaway-by-default exploration run to answer one uncertain question fast — usually by the beekeeper with a model (Gemini, Claude) outside the normal sprint/PR flow. The spike's *artifacts* often live wherever they were made (a scratch repo, a `Tests/` folder, a model session); what lives **here** is the **review** of a spike: a durable, reviewable write-up that

- states what the spike was and where its artifacts are,
- assesses the work honestly (coherence, and the epistemic status of each claim under the four-bucket / decision-boundary discipline — `conversation-modus-operandi.md` §10b, `decision-boundary.md`),
- separates what is *grounded* from what is *napkin/over-claimed*, and
- frames what (if anything) should graduate into real federation work (an issue, a proof obligation, a conversation).

A spike review is **not a ratification**. It is a review artifact so a promising spike can be picked up deliberately — and an over-claimed one caught — rather than either vanishing or leaking unearned status into the record.

**Convention:** one file per spike review, dated: `YYYY-MM-DD-<slug>-spike-review.md`. Name the reviewer and the source artifacts; sort the claims into buckets; end with the concrete next step (or "park it").
